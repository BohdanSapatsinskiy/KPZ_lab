# Принципи програмування в проекті

## 1. **DRY (Don't Repeat Yourself)**
Принцип DRY полягає в уникненні дублювання коду. У цьому проекті мінімізовано дублювання через правильне використання класів та методів. Наприклад, додавання тварин або співробітників виконується через загальні методи в класі `Zoo`, що дозволяє уникнути повторення логіки додавання даних.

**Файл**: [`Zoo.cs`](./Zoo.cs)

**Рядки**: [`10–28`](./Zoo.cs#L10-L28)

## 2. **KISS (Keep It Simple, Stupid)**  
Принцип KISS сприяє тому, щоб код був простим і зрозумілим. Кожен клас і метод у цьому проекті має одну чітку задачу. Наприклад, клас `Zoo` не містить зайвих методів, а лише основні функції для додавання та виведення інформації про тварин, працівників, вольєри та корм. Класи `Animal`, `Food`, `Employee` та `Enclosure` також чітко розмежовують свої відповідальності: `Animal` займається лише інформацією про тварин, `Food` відповідає за дані про корм, `Employee` містить дані про працівників зоопарку, а `Enclosure` — за зберігання даних про вольєри.

**Файли**: [`Zoo.cs`](./Zoo.cs), [`Animal.cs`](./Animal.cs), [`Food.cs`](./Food.cs), [`Employee.cs`](./Employee.cs), [`Enclosure.cs`](./Enclosure.cs)  

## 3. **SOLID - S (Single Responsibility Principle)**  
Принцип єдиної відповідальності вимагає, щоб кожен клас мав лише одну відповідальність. У проекті клас `Animal` займається лише зберіганням та наданням інформації про тварину, не включаючи в себе поведінку чи взаємодію з іншими класами. Клас `Food` відповідає лише за зберігання інформації про корм, клас `Employee` займається лише інформацією про працівників зоопарку, клас `Enclosure` тільки за збереження даних про вольєри.

**Файли**: [`Animal.cs`](./Animal.cs),
[`Food.cs`](./Food.cs),
[`Employee.cs`](./Employee.cs),
[`Enclosure.cs`](./Enclosure.cs)

## 4. **SOLID - O (Open/Closed Principle)**  
Класи повинні бути відкриті для розширення, але закриті для змін. Наприклад, у проекті додавання нових типів тварин, таких як `Carnivore` або `Herbivore`, не вимагає зміни існуючого коду класу `Animal`.

**Файл**: [`Animal.cs`](./Animal.cs),  
**Рядки**: [`61–74`](./Animal.cs#L61-L74)

## 5. **SOLID - L (Liskov Substitution Principle)**  
Принцип заміщення Лісков вимагає, щоб об'єкти, створені з підкласів, могли заміщати об'єкти базового класу без порушення правильності роботи програми. У нашому проекті, підкласи `Feeder`, `Cleaner` та `Supervisor` заміщають базовий клас `Employee`, і їх можна використовувати без змін у програмі.

**Файл**: [`Program.cs`](./Program.cs)  
**Рядки**: [`28-30`](./Program.cs#L28-L30)

## 6. **YAGNI (You Aren't Gonna Need It)**
Принцип YAGNI полягає в тому, щоб не додавати функціональність до того, як вона стане потрібною. У проекті створено лише необхідні класи та методи. 

## 7. **Composition Over Inheritance**  
Принцип композиції над наслідуванням використовується у цьому проекті для забезпечення гнучкості та зручності. Клас `Zoo` містить списки різних об'єктів (тварини, співробітники, вольєри, їжа), а не наслідує їх.

**Файл**: [`Zoo.cs`](./Zoo.cs)  
**Рядки**: [`5–8`](./Zoo.cs#L5-L8)


## 8. **Fail Fast**
Принцип "Fail Fast" передбачає, що програма повинна швидко інформувати користувача або розробника про помилки. У даному проекті перевірки на помилки, як наприклад перевірка на коректність даних співробітників, кормів, вольєрів та тварин, допомагають уникнути помилок.

**Файл**: [`Food.cs`](./Food.cs), [`Employee.cs`](./Employee.cs), [`Enclosure.cs`](./Enclosure.cs), [`Animal.cs`](./Animal.cs)

**Рядки**: [`10-50`](./Food.cs#L10-L55), [`20-83`](./Employee.cs#L20-L83), [`8-23`](./Enclosure.cs#L8-L23), [`10-56`](./Animal.cs#L10-L56)
